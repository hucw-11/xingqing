## 1. 项目是什么

「心晴」是一个**个人自用的安卓 App**，目标是把用户日常的几件事集中到一台手机上：

- 随手记录心情（任意时刻、可选原因）
- 写日记、周记
- 课程表与上课提醒（提前 5/15/30/60 分钟或上课时）
- 每天的计划安排（清单 + 连续时间轴，未实现）
- 每日天气提醒（未实现）
- 三餐记录与用餐时间汇总（未实现）

本地优先：数据保存在手机 Room 数据库，不上传、不加密；唯一会联网的功能是天气（Open-Meteo）。

## 4. 用户提出过的全部需求与反馈

### 4.1 最初需求
1. 日程提醒：录入课程表，提前 15 分钟提醒；也能设置普通日程。
2. 随时记录心情；写周记和日记。
3. 手机和电脑同步（**已决定暂缓**，第一版纯本地；未来再做同步和电脑端）。

### 4.2 技术路线决策
- 手机是安卓，用户想自己维护代码。
- 曾讨论 Flutter、Capacitor、原生 Kotlin；最终选择 **原生 Kotlin + Compose**。
- 构建方式选择 **GitHub Actions 云端编译**，本机不装 Android Studio。
- App 名定为「心晴」。

### 4.3 后续确认的产品细节
- **心情与日记独立**：心情是任意时刻的独立记录（5 档感受 + 可选原因）；日记是一天的总结，不强制关联心情。
- **计划模块**：要清单（待办）和时间轴两种视图。
- **连续时间轴**：昨天、今天、明天连在一起，同时显示课程和计划。
- **课程模型**：周几 + 开始时间 + 开始周 + 持续周数；支持单双周；支持调课/停课。
- **一门课一周多天**（最新反馈，**待实现**）：同一门课可能在周一周三同一时间上。
- **提醒方式**：静音 / 仅振动 / 声音+振动三档；用户以为「提醒」是闹钟，实际是通知；希望有更明显的提醒方式（振动；未来可评估全屏闹钟）。
- **心情汇总**：五档心情占比 + 趋势（按天/周）。
- **天气提醒**：每天约 7:00 推送今日天气、是否降温、是否带伞；数据源 Open-Meteo；手动选择城市，不申请定位。
- **三餐记录**：独立模块，可拍照 + 文字，记录「有没有好好吃饭」；汇总各餐次用餐时间、漏餐次数；预留照片热量评估接口；备份不含照片。
- **数据迁移**：未来希望导入网页版「慢慢记」的旧备份（JSON）。

### 4.4 测试反馈（按时间顺序）
1. 第一版 5 分钟测试没有响 → 实际原因是首次点击只申请了通知权限、没有排闹钟；已修复并增加诊断面板。
2. 用户发现提醒是通知不是闹钟；希望能选静音/振动/声音。
3. 手机正常模式只有通知，**没有振动** → 已补 `VIBRATE` 权限和渠道振动模式；**用户复测仍不振动** → 本轮新增「直接调用系统振动器」+「振动测试」按钮，待验证。
4. 课程时间录入太呆板 → 已改为小时/分钟轮盘，去掉结束时间，改为「持续分钟数」自动推导结束时间。
5. 一门课一周可能上两天同一时间 → **待实现**。
6. 周视图很丑、看不清 → **待重做**。
7. 停课/调课功能正常（已确认可用）。

## 7. 关键机制

### 7.1 学期与周次
- 设置里保存「学期第一个周一」（`SettingsStore`）；第 1 周从这天起算。
- 每门课存 `startWeek` + `weekCount`，`endWeek = startWeek + weekCount - 1`。
- 单双周：`weekNumber % 2`，单周为奇数周。
- **当前课程只有一个 `weekday`**；多天需求待改（见 10.2）。

### 7.2 提醒排期
- `AlarmScheduler.rescheduleAll()`：取消数据库里记录的所有闹钟 → 清空 → 按未来 **21 天**重新规划（上限 200 条）。
- 每个实例插入 `scheduled_alarms` 得到自增 id，**用 id 作为 PendingIntent 的 requestCode**，并给 Intent 设置唯一 data URI `xinqing://course-reminder/{id}`，保证取消/重排不串。
- 精确闹钟权限可用时 `setExactAndAllowWhileIdle`，否则降级 `setAndAllowWhileIdle`，并捕获 `SecurityException`。
- 触发时 `CourseReminderReceiver` 会重新查库：课程/例外已变化或不存在就不发通知；发完通知后再次重排，滚动补足窗口。
- 重排触发点：App 启动、课程增删改、调课/停课、学期变更、开机、`MY_PACKAGE_REPLACED`、时区/时间/日期变化。
- **已知局限**：如果 21 天内一次都没打开 App、也没有任何提醒触发，窗口不会自动续期；需要时加一个维护闹钟（例如每 3 天）。
- 调课/停课的例外存在 `course_exceptions`：`CANCELLED` 去掉原实例，`MOVED` 增加新日期时间；`Recurrence` 在展开时应用。

### 7.3 提醒方式
- 三个渠道：`reminders_sound`（声音+振动）、`reminders_vibrate`（仅振动）、`reminders_silent`（静音）。
- 课程上可选提醒方式；通知落到对应渠道。
- **振动问题**：c488c1a 补了 `android.permission.VIBRATE` 与渠道振动模式，但用户复测仍不振动。本轮在 `Notifications.show()` 成功后额外调用 `Vibration.vibrate()` 直接驱动系统振动器，并在「今天」页加了「振动测试」按钮。
- 若仍不振动，按顺序排查：系统「声音与振动 → 通知振动」是否开启；应用通知 →「提醒（声音+振动）」渠道的振动开关；勿扰模式；厂商省电/触感设置。
- 注意：通知渠道创建后，代码无法修改用户已调整的振动/声音设置；必要时可换新 channel id 或引导用户手动开。

### 7.4 诊断
- `Diagnostics` 记录最近 8 条事件（安排、触发、通知是否发出），首页可见。
- `scheduledAt` 记录最近一次测试提醒时间；`triggerCount` 记录触发次数。

## 10. 已知问题与下一步设计

### 10.1 振动（最高优先验证）
- 已做：`VIBRATE` 权限、渠道振动模式、直接振动器、振动测试按钮。
- 验证：首页点「振动测试」，应立刻长振动；再点「10 秒后快速测试」确认通知到达时同时振动。
- 若直接振动有效但通知不振动：问题在渠道/系统通知振动设置；考虑用 `Vibration` 直接振动作为通知触发的补充（已实现），无需依赖渠道。

### 10.2 一门课多个星期（待实现）
建议改法（注意数据库迁移）：
1. `CourseEntity` 增加 `weekdays: String`（如 `"1,3"`），保留 `weekday` 兼容；数据库 version → 2，Migration：
   `ALTER TABLE courses ADD COLUMN weekdays TEXT NOT NULL DEFAULT ''`，再 `UPDATE courses SET weekdays = CAST(weekday AS TEXT)`。
2. 领域模型 `Course` 增加 `weekdays: List<Int>`；`Recurrence.occursOn` 改为 `date.dayOfWeek.value in course.weekdays`。
3. 冲突检测：两门课只要有共同的星期、时间重叠、周次重叠就算冲突。
4. 课程编辑页：把「星期」下拉改成 7 个可多选的标签/复选框。
5. 排期逻辑不需要改（按日期展开）。
6. 周视图显示不变。

### 10.3 周视图重做（用户反馈：丑、看不清）
建议方案：
- 采用**垂直时间轴 + 7 列**的课程表：左侧 07:00–22:00 时间刻度，顶部固定星期表头；课程块按开始时间定位、按持续分钟决定高度；块内显示课程名、地点、时间。
- 配色改为「浅色底 + 左侧 3dp 色条 + 深色文字」，提高对比度；今天列加浅色背景与顶部圆点。
- 字号加大（课程名至少 13sp），列宽不小于 56dp；整个表格横向滚动、纵向固定高度并内部滚动。
- 顶部显示「第 N 周」与日期范围，左右切换周。
- 可保留「全部课程」列表作为编辑入口；点课程块进入调课页。

### 10.4 其他
- 提醒窗口 21 天续期：可加维护闹钟或每日打开时重排（目前每次启动会重排）。
- 首页诊断内容越来越多，后续应把诊断移到设置页，首页聚焦心情/课程/计划。
- `HomeScreen` 目前兼作「今天」页，M3 时重构。
- 多天课程改动时，注意 `ReminderPlanner`、`CourseReminderReceiver` 的二次校验也要用新的 `weekdays`。

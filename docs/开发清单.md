# 心晴 · 功能开发清单

标记：✅ 已完成　🔄 进行中　⬜ 待开发

## 当前状态

- ✅ 工程脚手架：Kotlin 1.9.24 + Compose + GitHub Actions 出 APK
- ✅ 提醒链路冒烟：1 分钟 / 10 秒测试提醒、通知渠道、权限引导、诊断记录（三连测进行中）
- ✅ 本地 git 与 GitHub（SSH 443）已打通，改动可直接 push

## 已确认的产品决策

- 心情与日记独立：心情任意时刻记录、可写原因；日记是一天的总结
- 时间轴连续：昨天、今天、明天不中断，同时显示课程与计划
- 课程：每门课设开始周 + 持续周数，支持调课 / 停课
- 心情汇总：五档占比 + 趋势
- 天气：Open-Meteo、手动选择城市、每天早上 7 点提醒今日天气 / 是否降温 / 是否带伞
- 三餐：独立记录，可拍照和写文字，汇总用餐时间；备份不含照片；预留热量评估接口
- 提醒方式：静音 / 仅振动 / 声音+振动三档可选；更明显的闹钟式强提醒作为增强项后续评估

## M1 数据层与页面骨架 ⬜

目标：Room 跑通，五个页面能切换，数据重启不丢。

- [ ] 类型转换：`LocalDate` / `LocalTime` / `Instant` / 标签列表
- [ ] DAO 与仓库层；手动 `AppContainer`（不引入 Hilt，降低 CI 风险）
- [ ] 底部导航：今天 / 日记 / 课表 / 回顾 / 设置
- [ ] 设置存储：学期起始周一、提醒总开关

验收：切页不崩；写一条测试数据，杀进程重开仍在。

## M2 课程表与提醒（核心） ⬜

目标：这是网页版做不到、这个 App 存在的最大理由，优先做。

- [ ] 课程录入：名称、周几、上课时间、开始周、持续周数、地点、老师、颜色
- [ ] 学期起始周一 + 单双周（单周 / 双周 / 每周）
- [ ] 调课 / 停课：把某一次课改到任意日期时间，或标记停课；调课参与冲突检测与提醒重排
- [ ] 周视图：7 列网格、上一周/下一周/本周、今日高亮
- [ ] 冲突检测：同周几 + 时间严格重叠 + 日期有交集；互补单双周不算冲突；保存前提示但允许保存
- [ ] 滚动排期：未来 21 天，最多 200 个闹钟，每次变更全量重排
- [ ] 唯一闹钟标识：数据库自增 id 作 `requestCode` + `xinqing://course-reminder/{id}`
- [ ] 重排触发：App 启动、课程变更、开机、时区变化、手动改时间、系统更新
- [ ] 触发时二次查库，课程已删则不弹通知
- [ ] 通知点击打开课表
- [ ] 提醒方式可选：静音 / 仅振动 / 声音+振动（用不同通知渠道实现）
- [ ] 增强项：闹钟式强提醒（全屏提醒 + 循环铃声 + 手动停止），后续评估系统权限限制
- [ ] 单元测试：日期展开、单双周、学期边界、冲突判定

验收：录课 → 提前 15 分钟准时提醒；杀进程 / 锁屏 / 重启仍响；删课后不再提醒。

## M3 今天页：心情与计划 ⬜

- [ ] 今日问候、今日课程、「下一节」卡片
- [ ] 心情独立记录：任意时刻选 5 档感受，可选记录原因；日记是一天的总结，两者互不强制关联
- [ ] 计划项：文本、日期、可选起止时间、完成勾选
- [ ] 连续时间轴：昨天、今天、明天不断开，同时显示课程与计划；打开时自动定位到当前时刻
- [ ] 清单视图 / 时间轴视图切换（同一份数据）
- [ ] 计划项可选提醒时间

验收：心情随手可记、与日记互不影响；时间轴跨天连续；两种视图数据一致；计划提醒能触发。

## M4 日记 ⬜

- [ ] 一天可记多条；编辑保留创建时间，单独显示最近修改
- [ ] 草稿自动保存与恢复

验收：编辑不乱序、不新建；搜索能命中标题 / 正文 / 标签 / 日期。

## M7 天气提醒 ⬜

- [ ] 手动选择城市：用 Open-Meteo 的地理编码接口搜索城市，保存名称与经纬度（不申请定位权限）
- [ ] 每日 7:00 推送天气提醒：今日温度区间、相比昨天是否降温、降水概率与是否建议带伞
- [ ] 提醒时间可调，可单独关闭天气提醒
- [ ] 断网时使用最近一次缓存并注明「缓存数据」
- [ ] 新增 `INTERNET` 权限；仅开启天气提醒时联网

验收：把提醒时间临时改到 1 分钟后，能收到包含温度与带伞建议的通知；飞行模式下显示缓存。

## M8 三餐记录 ⬜

- [ ] 记录条目：日期、餐次（早 / 午 / 晚 / 加餐）、时间、文字备注、照片

- [ ] 三餐汇总：各餐次平均用餐时间、最早 / 最晚时间、漏餐次数，按周查看

- [ ] 预留 `MealAnalyzer` 接口：输入照片路径、返回营养或热量估算（本期只留空实现）

验收：拍照记录一餐；汇总页能显示本周各餐次平均时间与漏餐次数。

## 建议节奏

每个里程碑 = 一次开发 + 一次 CI 构建 + 一次真机检查。M1 和 M2 可以合并成一次提交，减少等待；之后每完成一个模块提交验证一次。

提醒相关（M2）建议排在最前，因为通知是本 App 相对网页版的核心价值；日记与回顾可以稍后，但网页版已有数据，M6 的导入功能建议尽早验证兼容性。天气和三餐可以放在 M6 之后，彼此独立，按兴趣顺序做即可。
